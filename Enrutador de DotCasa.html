Enrutador de DotCasa

1. Conceptos Fundamentales

  • El Servidor / Cloudflare Worker (Punto de Intercepción): Actúa como el controlador de acceso principal de la arquitectura. Cada vez que un usuario ingresa una URL (ej. dotcasa.com.mx/casa/venta), este servicio evalúa, estandariza y dirige la solicitud antes de consultar la base de datos (Bubble) para verificar su existencia.
  • Request (Petición HTTP): La solicitud de información emitida por el navegador del cliente.
  • Response (Respuesta HTTP): La información procesada y devuelta por el servidor al cliente.
  • Proxy: Funciona como un intermediario tecnológico. En lugar de permitir una conexión directa a Bubble, el tráfico pasa primero por este código, el cual procesa la información y la entrega al cliente final.
  • Bubble: La plataforma que funge como sistema de gestión de base de datos y constructor de la interfaz visual del sitio.

El sistema está modularizado en distintos archivos y directorios para separar responsabilidades operativas. A continuación, se detalla la estructura lógica del código.

Archivos de Configuración de Infraestructura

wrangler.toml y .dev.vars

Estos archivos no contienen lógica de programación, sino que definen los parámetros operativos y variables de entorno requeridas por la plataforma de Cloudflare.

Ini, TOML

name = "dotcasa-router"
main = "src/index.js"
compatibility_date = "2024-03-01"
  • name: Identificador oficial del proyecto en la plataforma ("dotcasa-router").
  • main: Define el archivo de entrada o núcleo de ejecución (index.js).
  • compatibility_date: Parámetro técnico que indica a Cloudflare la versión específica del entorno de ejecución a utilizar.

Fragmento de código

BUBBLE_BASE_URL="https://dotcasa.com.mx"
  • Variable de entorno: Funciona como una credencial o ruta almacenada de manera segura. El sistema consulta esta variable para determinar el dominio destino hacia el cual debe enrutarse el tráfico.

Resumen Operativo para la Mantenibilidad del Sistema

  • Adición de Entidades: La inclusión de nuevos tipos de inmuebles (ej. "edificio") requiere modificación exclusiva en el módulo src/controllers/config/config.js dentro del catálogo TIPOS.
  • Gestión de Rendimiento (Caché): Los tiempos de latencia y frecuencia de actualización se ajustan modificando la variable CACHE_SEGUNDOS en el módulo de configuración.
  • Arquitectura de Rutas: Toda reestructuración en el formato de URIs dependientes de Bubble (ej. alterar el directorio "/buscador/") debe aplicarse invariablemente dentro de la clase AppRouter (AppRouter.route.js).
